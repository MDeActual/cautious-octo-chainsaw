# CloudMatrix Customer-First Commercial Platform — Integration Plan

Status: proposal only; no production behavior changed.
Source: CloudMatrix founder's instructions and the grant-oriented source files preserved under docs/grant-origin/.
Destination: cautious-octo-chainsaw. DevOS remains an independent execution/governance system.

## Founding promise
Provide substantial, accurate, self-service value before asking for a sales call, contact details, or purchase. Never mislead about risk, funding eligibility, savings, compliance, AI benefits, or what the product has actually verified. Make every permission request understandable and optional, and explain what information is accessed and for what purpose.

## Proposed capability boundaries (not claims of implementation)
- discovery: educational, no sign-in required
- consent: Entra login and separately authorized Graph read access; scoped write consent or GDAP only for justified fulfillment. PAL is attribution, not consent.
- assessment: evidence and timestamps, Secure Score and clearly labeled gaps; distinguish real Microsoft telemetry from mock/demo results
- recommendations: transparent control-to-remediation mapping, DIY option and appropriately scoped purchasable service packages; disclose uncertainty and commercial interest
- affordability: funding-program discovery with source, date checked, eligibility conditions, exclusions, deadlines, applicant responsibilities and **no approval guarantee**; phased-payment alternatives when applicable
- commerce: itemized, non-inflated quotes; estimates clearly marked; authentic invoices only for real transactions; no backdating or eligibility manipulation
- onboarding: agreements, explicit permissions and scope, audit records and revocation path
- delivery: human-approved remediation, least privilege, change verification, rollback plan
- assurance: before/after evidence and recurring rechecks
- expansion: data governance, bilingual documentation, responsible AI workflows only when customer-ready

## Decision and acceptance checklist
- [ ] Verify reusable files, licenses, provenance, dependencies, and test results before integrating.
- [ ] Confirm real read-only Graph consent path and permissions; no sensitive access at ordinary login.
- [ ] Ensure each assessment labels source, date, uncertainty and mock-vs-live state.
- [ ] Offer an actionable free report and DIY remedies without an email requirement.
- [ ] Recommendations identify verified gaps, price, scope, assumptions, and an impartial no-purchase option.
- [ ] Funding suggestions cite live program pages and disclose date, conditions and no guarantee.
- [ ] Quotes reflect true work and eligible/noneligible distinctions; invoices reflect actual transactions.
- [ ] Stage additional permissions only for accepted scopes, with revocation and audit log.
- [ ] Verify customer/tenant isolation, secrets handling, security review and independent tests.
- [ ] Do not deploy or merge to main without review and founder approval.

## Smallest implementation slice
Prove one real tenant's consented Secure Score -> understandable free report -> transparent remediation mapping -> optional itemized quote -> accurate funding-information panel. Keep the funding step informational. Only implement purchase and write access after the read-only journey is demonstrated and security-reviewed.
